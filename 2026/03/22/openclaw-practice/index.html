我的 OpenClaw 实战：从零打造个人 AI 助手

背景

用大模型 API 做问答已经不够了——我需要的是一个真正能帮我做事的 AI 助手：帮我监控交易、查邮件、管文件、甚至在我不在的时候主动出击。想来想去，自己搭一个 AI Agent 是最靠谱的选择。

调研了一圈，最后选了 OpenClaw。选择它的理由很简单：开源、本地运行、可扩展、支持多渠道（Telegram、Discord 等），而且上手门槛不高。本文就是我从零到跑起来的完整记录，包括核心概念、踩过的坑和实战心得。

什么是 OpenClaw

OpenClaw 是一个开源的 AI Agent 运行时框架。它的核心思路是：给大模型装上手和脚——不只是聊天，而是能实际执行操作（读写文件、执行命令、访问网页、调用 API）。

关键组件：

  • Workspace：AI 的工作目录，所有文件、脚本、记忆都在这里
  • Memory：持久化记忆系统，分短期的每日笔记和长期的 MEMORY.md
  • Skills：可插拔的能力模块，发布在 ClawHub 上可以一键安装
  • Channel：对接各种消息渠道（Telegram、Discord、WhatsApp 等），一个 AI 多端在线
  • Subagents：支持派生子任务，主 agent 统筹调度

安装与基础配置

我是 Ubuntu 22.04 + AMD 7800X3D 的机器，OpenClaw 通过 npm 全局安装：

npm install -g openclaw
openclaw init
openclaw gateway start

配置文件在 ~/.openclaw/config.yaml，核心配置项：

model: minimax-portal/MiniMax-M2.5  # 主模型
skills:
  enabled:
    - coding-agent
    - discord
    - weather
    - clawhub
  channel:
    telegram:
      enabled: true
      bot_token: "YOUR_BOT_TOKEN"
踩坑经验：模型选择上，国产模型（MiniMax、GLM）在中文场景性价比很高，但复杂推理任务我会切到 Claude Opus。OpenClaw 支持会话级模型覆盖，很方便。

Workspace 结构设计

Workspace 是 AI 的"家"，结构要设计好。我的目录布局：

~/.openclaw/workspace/
├── AGENTS.md          # 运行规范和流程
├── SOUL.md            # AI 的灵魂和性格
├── USER.md            # 用户信息
├── IDENTITY.md        # AI 身份定义
├── HEARTBEAT.md       # 定期任务清单
├── MEMORY.md          # 长期记忆
├── TOOLS.md           # 本地工具备忘
├── memory/            # 每日工作记录
│   ├── 2026-03-22.md
│   └── heartbeat-state.json
├── scripts/           # 各种自动化脚本
│   └── quantrade-monitor.sh
└── exports/           # 输出文件

核心文件说明：

  • SOUL.md：定义 AI 的性格和风格，这个写好了，回复才有"人味"
  • HEARTBEAT.md：心跳任务清单，AI 会定期检查这些事项
  • MEMORY.md：长期记忆，AI 每次启动都会加载，决定了它的"认知连续性"

实战：量化交易监控

我的核心场景之一是用 OpenClaw 监控我的加密货币量化交易系统（Quantrade）。

监控脚本

写了一个 bash 脚本，定时查 MySQL，有新成交就推 Telegram：

#!/bin/bash
# Quantrade 交易监控脚本
STATE_FILE="/workspace/memory/quantrade-last-order-id.txt"
LAST_ID=$(cat "$STATE_FILE" 2>/dev/null || echo 0)

RESULT=$(mysql -h 127.0.0.1 -P 3307 -u root -proot123456 quantrade \
  -N -e "SELECT id, symbol, side, quantity, price, total, status, executed_at
         FROM t_quantrade_order WHERE id > $LAST_ID ORDER BY id ASC")

if [ -z "$RESULT" ]; then
    echo "NO_NEW_TRADES"
    exit 0
fi

# 发送到 Telegram
curl -s -X POST "https://api.telegram.org/bot$TOKEN/sendMessage" \

Heartbeat 任务

在 HEARTBEAT.md 里注册这个脚本，OpenClaw 会在心跳时自动运行：

# HEARTBEAT.md
## Quantrade 交易监控
运行 `bash ~/.openclaw/workspace/scripts/quantrade-monitor.sh`
- 脚本自动处理通知和状态更新
- 如果容器挂了 → 通知 Sam

Skills 生态

OpenClaw 的 Skills 系统让我不用重复造轮子。几个常用的：

  • weather：查天气预报，开箱即用
  • discord：Discord 渠道运营工具
  • coding-agent：把复杂编码任务丢给 Claude Code 子 Agent 来做
  • clawhub：搜索和安装社区 Skills
  • find-skills：查找某个功能有没有现成的 Skill

安装 Skill 很简单：

clawhub install weather

自己的 Skill 写起来也不难，核心就是一个 SKILL.md 定义工具和用法，放在 ~/.openclaw/workspace/skills/ 即可。

记忆系统设计

记忆系统是我认为 OpenClaw 最聪明的设计。分两层：

  1. 每日日志（memory/YYYY-MM-DD.md）：记录每天发生的事，不需要太讲究，随手记
  2. 长期记忆（MEMORY.md）：从每日日志里提炼出来的精华，AI 每次启动必读

AI 会定期（通过 heartbeat）做"记忆整理"：读最近几天的日志，提炼重要内容更新到 MEMORY.md。这模拟了人类"事后复盘"的过程。

关键原则：别什么都往 MEMORY.md 里塞。只留真正重要的决策、教训、偏好。MEMORY.md 越大，每次启动越慢，效果反而差。

踩过的坑

  1. 磁盘只读：外接 HDD 挂载成了 ro 模式，写入失败。后来查了 mount 输出，发现是 NTFS 格式需要额外参数重新挂载
  2. heartbeat 过频：一开始设了 5 分钟一次，API 调用飞起。改成 30 分钟，并按功能分批处理
  3. 模型选择：便宜模型响应快但复杂任务容易出错。关键任务（交易监控）用好模型，日常闲聊用便宜模型
  4. 私有信息泄露：MEMORY.md 里有敏感信息，坚决不在群聊里加载。AGENTS.md 里明确写了"不在共享上下文里读 MEMORY.md"

总结

用 OpenClaw 跑了几个月下来，最大的感受是：AI Agent 真正的价值在于自动化——不是问它答，而是让它主动帮我盯着事情、做记录、推提醒。

它不一定完美，但足够实用。关键是设计好 Memory 系统和 Heartbeat 任务，让它真正成为一个"活的"助手，而不是每次都要重新解释上下文的陌生人。

下一步的打算是接入更多 Skills（比如日历、邮件），以及让 Subagents 处理更复杂的分析任务。有兴趣的可以去看看 OpenClaw 官方文档 和 ClawHub。
